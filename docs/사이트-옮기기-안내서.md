# 사이트 옮기기 안내서

이 사이트를 **다른 GitHub 저장소**와 **다른 Supabase 프로젝트**로 옮기는 방법입니다. 모두 무료 요금제로 됩니다.
한 번에 한 단계씩 하세요. 막히면 그 단계 번호와 화면에 나온 글자를 그대로 알려 주세요.

옮기기 전에 알아 둘 것
- 새 Supabase는 **빈 서버**입니다. 회차·신청·결과 기록은 옮겨지지 않습니다. 필요한 회차는 옛 사이트에서 결과 엑셀·명단 CSV를 먼저 받아 두세요.
- 운영자는 새 사이트에서 다시 초대·승인해야 합니다.
- 사이트는 `config.js`의 `allowedHosts`에 적힌 주소에서만 열립니다. 다른 주소에서 열면 **픽셀 바나나 그림**만 보이고 서버에 연결하지 않습니다. 옮길 때 8단계에서 새 주소로 바꿉니다.

---

## 1. 파일 받기

둘 중 하나로 사이트 파일 전체(압축 파일)를 받습니다.
- Claude가 보내 준 `tournament-auction.zip`
- 또는 옛 GitHub 저장소 → 초록색 **Code** 버튼 → **Download ZIP**

받은 파일의 압축을 풉니다. 안에 `index.html`, `setup.sql`, `config.js`, `agents` 폴더, `docs` 폴더, `.github` 폴더가 있어야 합니다.
- `.github` 폴더는 이름이 점(.)으로 시작해서 숨겨져 보일 수 있습니다.
  - 윈도우: 탐색기 위쪽 **보기** → **표시** → **숨긴 항목** 체크
  - 맥: 폴더 창에서 `Cmd + Shift + .` (마침표)

## 2. 새 GitHub 저장소에 올리기

1. 새 GitHub 계정으로 로그인 → 오른쪽 위 **+** → **New repository**
2. 이름을 적고(예: `Tournament-Auction`) **Public**(공개)을 고릅니다. 무료 GitHub Pages는 공개 저장소에서만 됩니다.
3. **Create repository**
4. 새 저장소 화면에서 **uploading an existing file** 링크(또는 **Add file** → **Upload files**)
5. 압축을 푼 폴더 **안의 것 전부**(파일과 폴더 모두, `.github` 포함)를 끌어다 놓습니다.
6. 아래 **Commit changes**

확인: 저장소 첫 화면에 `.github` 폴더가 보여야 합니다. 없으면 5번에서 `.github` 폴더만 다시 끌어다 놓으세요(숨긴 항목 보이게 한 뒤).

## 3. 사이트 켜기 (GitHub Pages)

1. 저장소 → **Settings** → 왼쪽 **Pages**
2. **Source**를 **GitHub Actions**로 고릅니다.
3. 저장소 → **Actions** 탭 → **Deploy site to GitHub Pages** → **Run workflow** (초록 버튼이 없으면 1~2분 기다리면 자동으로 돕니다)
4. 끝나면 사이트 주소는 `https://새아이디.github.io/저장소이름/` 입니다. 이 주소를 적어 두세요.

지금 이 주소를 열면 바나나만 보이는 게 정상입니다(8단계 전이라서).

## 4. 새 Supabase 프로젝트 만들기

1. https://supabase.com/dashboard 에 로그인 → **New project**
2. 이름을 적고, 데이터베이스 비밀번호는 아무 데나 따로 적어 두고(사이트에는 안 씀), 지역은 **Northeast Asia (Seoul)**, 요금제는 **Free**
3. 만들어지면 왼쪽 **SQL Editor** → **New query**
4. 1단계에서 받은 `setup.sql` 파일을 메모장으로 열어 **전체 복사** → 붙여 넣기 → **Run**
5. "Success. No rows returned"가 나오면 끝

## 5. 주소와 공개 키 복사

1. Supabase 왼쪽 아래 **Project Settings**(톱니바퀴)
2. **Data API**(또는 **API**)에서 **Project URL** 복사 — `https://영문숫자.supabase.co` 모양
3. **API Keys**에서 **Publishable key** 복사 — `sb_publishable_`로 시작

절대 복사하지 말 것: **secret** 키(`sb_secret_`로 시작)와 **service_role** 키. 이 두 개는 사이트에 넣으면 안 됩니다.

## 6. 디스코드 로그인 연결

디스코드 쪽
1. https://discord.com/developers/applications → **New Application** → 이름 적고 만들기
2. 왼쪽 **OAuth2** → **Redirects**에 아래 주소를 추가하고 저장
   `https://영문숫자.supabase.co/auth/v1/callback` (5단계의 Project URL 뒤에 `/auth/v1/callback`)
3. 같은 화면의 **Client ID**와 **Client Secret**(Reset Secret을 눌러 새로 만들기)을 복사

Supabase 쪽
4. 왼쪽 **Authentication** → **Sign In / Providers**(또는 **Providers**) → **Discord** → 켜기
5. Client ID, Client Secret 붙여 넣기 → **Save**
6. 같은 목록의 **Email**은 꺼 두세요. 이 사이트는 디스코드 로그인만 씁니다.

Client Secret은 채팅이나 사이트 파일에 올리지 마세요.

## 7. 로그인 후 돌아올 주소

1. Supabase → **Authentication** → **URL Configuration**
2. **Site URL**에 3단계의 사이트 주소(`https://새아이디.github.io/저장소이름/`)
3. **Redirect URLs**에 `https://새아이디.github.io/저장소이름/**` 추가 → **Save**

## 8. config.js 고치기

1. 새 GitHub 저장소 → `config.js` 클릭 → 오른쪽 위 연필(Edit)
2. 세 줄을 바꿉니다.
   ```js
   supabaseUrl: "5단계의 Project URL",
   supabaseKey: "5단계의 sb_publishable_ 키",
   allowedHosts: ["새아이디.github.io"],
   ```
   - `allowedHosts`에는 `https://`와 저장소 이름 없이 **`새아이디.github.io`만** 적습니다.
   - 자기 도메인을 따로 연결했다면 그 도메인도 넣습니다. 예: `["새아이디.github.io", "auction.example.com"]`
3. **Commit changes** → 1~2분 뒤 사이트가 새로 배포됩니다.

이제 사이트 주소를 열면 바나나 대신 첫 화면이 보여야 합니다. 바나나가 계속 보이면 `allowedHosts`의 철자와 따옴표를 확인하고, 새로고침(Ctrl+F5) 해 보세요.

## 9. 제작자(주인) 등록

1. 새 사이트 첫 화면 → **새 온라인 경매 만들기**
2. 열린 진행자 화면 위쪽 **운영자 콘솔** 버튼
3. **디스코드로 로그인** → **제작자로 등록**
4. 이제 운영자 콘솔에서 회차를 만들고, **운영자 관리 · 초대**에서 운영자를 다시 초대합니다.

## 10. 자동 작업 켜기

1. 저장소 → **Actions** → **Keep Supabase awake** → (보이면 **Enable workflow**) → **Run workflow**
   - 초록 체크가 나오면 3일마다 서버를 깨워 무료 요금제가 멈추지 않습니다.
2. 새 요원이 나오면 **Update agent icons** → **Run workflow** (요원 아이콘은 이미 파일에 들어 있어서 지금은 안 해도 됩니다)

## 11. (선택) 안내서 속 옛 주소 고치기

`README.md`와 `docs` 폴더의 안내서에는 옛 사이트 주소가 적혀 있습니다. 사이트 동작과는 상관없고, 원하면 새 주소로 바꾸면 됩니다.

---

## 옮긴 뒤 확인 목록

- [ ] 새 사이트 주소에서 첫 화면이 보인다 (바나나 아님)
- [ ] 운영자 콘솔에서 디스코드 로그인이 된다
- [ ] 제작자로 등록됐다
- [ ] 연습판(`practice.html`)이 돌아간다
- [ ] Actions의 **Keep Supabase awake**가 초록 체크
- [ ] 다른 주소(예: 저장소를 복사한 다른 사람의 주소)에서 열면 바나나만 보인다

## 자주 막히는 곳

- **바나나만 보여요** → `config.js`의 `allowedHosts`에 지금 주소가 정확히 들어 있는지 확인 (예: `"새아이디.github.io"`, 대소문자 상관없음).
- **로그인 후 옛 사이트로 가요 / 에러 페이지가 떠요** → 7단계의 Site URL·Redirect URLs, 6단계의 디스코드 Redirects 주소 확인.
- **사이트 주소가 404예요** → 3단계 Source가 GitHub Actions인지, Actions 탭에서 **Deploy site to GitHub Pages**가 초록 체크인지 확인. `.github` 폴더가 올라갔는지 확인.
- **SQL에서 빨간 오류** → 오류 글자를 그대로 복사해서 알려 주세요. `setup.sql`은 여러 번 실행해도 됩니다.
