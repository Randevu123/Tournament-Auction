# 제작자 안내서

사이트 주인(**제작자**)을 위한 안내서입니다. 운영자·진행자가 하는 일은 [운영자 안내서](운영자-안내서.md), [진행자 안내서](진행자-안내서.md)를 보세요.
제작자는 운영자·진행자가 할 수 있는 일을 모든 회차에서 할 수 있고, 아래 일은 제작자만 합니다.

사이트가 쓰는 곳 (모두 무료 요금제)
- 사이트: GitHub Pages — https://randevu123.github.io/Tournament-Auction/
- 코드: GitHub 저장소 Randevu123/Tournament-Auction
- 서버·데이터베이스·디스코드 로그인: Supabase (무료 요금제)

---

## 1. 운영자 초대·승인·빼기 (운영자 콘솔 → 운영자 관리 · 초대)

1. 콘솔 왼쪽의 **운영자 관리**를 누릅니다.
2. **운영자 초대 링크**를 복사해 운영자가 될 사람에게 **개인 메시지**로 보냅니다.
3. 그 사람이 디스코드로 로그인해 요청을 보내면 목록에 "승인 대기"로 뜹니다.
4. **승인** 또는 **거절**을 누릅니다.
5. 운영자를 그만두게 하려면 **빼기**를 누릅니다.

- 초대 링크가 새어 나갔으면 **새 링크로 바꾸기**. 예전 링크는 바로 못 쓰게 됩니다.
- 진행자(회차를 맡은 운영자)와 모든 회차 진행 권한을 받은 운영자도 초대 링크를 보내고 **승인·거절**할 수 있습니다. **빼기**와 **새 링크로 바꾸기**는 제작자만 합니다.

### 모든 회차 진행 권한 (예: 요한님)
- 운영자 목록에서 그 사람 옆 **모든 회차 진행 권한 주기**를 누릅니다. 이름 옆에 "모든 회차 진행" 표시가 붙습니다.
- 이 권한을 받은 운영자는 제작자처럼 모든 회차의 경매 준비, 진행자 화면, 팀장 링크, 회차 지우기를 할 수 있고, 운영자 초대·승인도 할 수 있습니다.
- 되돌리려면 **모든 회차 진행 권한 빼기**. 누가 언제 주고 뺐는지 기록에 남습니다.
- 같은 화면 아래에 **사이트 전체 기록**(누가 언제 무엇을 했는지)이 있고 CSV로 받을 수 있습니다.

## 2. 지난 회차 잠금 풀기

- 경매가 끝났거나 경기 날짜가 지난 회차는 자동으로 잠겨서 참가자 고치기와 설정을 바꿀 수 없습니다.
- 꼭 고쳐야 하면 그 회차의 잠금 안내 옆 **잠금 풀기**를 누르고, 다 고친 뒤 **다시 잠그기**를 누르세요.
- 그 회차의 진행자와 모든 회차 진행 권한자(예: 요한님)도 잠금 풀기·다시 잠그기를 할 수 있습니다. 누가 했는지 기록에 남습니다.

## 3. 서버 상태와 무료 요금제 (가장 중요)

Supabase 무료 요금제는 **7일 동안 쓰지 않으면 서버가 멈춥니다.**

- **자동 깨우기**: GitHub Actions가 3일마다 서버를 한 번 불러서 멈추지 않게 합니다(설정 완료, 따로 할 일 없음).
- **내전 전날 확인**: 운영자 콘솔 위쪽에 **서버 정상 · 00ms**가 뜨는지 봅니다. 누르면 서비스 상태 카드가 열립니다.
  - 마지막 사용, 데이터베이스 사용량(무료 500MB), 그중 선수 사진 용량, 회차·신청 수, 마지막 자동 깨우기
- **서버가 멈췄을 때** (콘솔에 "서버에 연결되지 않아요"):
  1. https://supabase.com/dashboard 에 로그인
  2. 이 프로젝트를 열고 **Restore project**(다시 켜기)
  3. 몇 분 뒤 콘솔을 새로고침
- **자동 깨우기가 꺼졌을 때**: 공개 저장소는 60일 동안 저장소에 아무 변경이 없으면 GitHub이 예약 작업을 끕니다. GitHub 저장소 → **Actions** → **Keep Supabase awake** → **Enable workflow**(보이면) → **Run workflow**.

저장 공간
- 선수 사진이 가장 큰 부분입니다. 사용량이 350MB를 넘으면 상태 카드에 경고가 뜹니다.
- 끝난 회차의 **일정 · 신청 마감** 탭에서 **이 회차 선수 사진 지우기**로 줄이세요.

## 4. 업데이트가 있을 때 (SQL 실행)

제가(Claude) 기능을 고치면서 "SQL을 한 번 더 실행해 주세요"라고 할 때가 있습니다.

1. GitHub 저장소의 **setup.sql** 파일을 열고 전체를 복사합니다.
   https://github.com/Randevu123/Tournament-Auction/blob/main/setup.sql
2. https://supabase.com/dashboard → 이 프로젝트 → **SQL Editor** → 새 쿼리
3. 붙여 넣고 **Run**

- 여러 번 실행해도 기존 데이터는 지워지지 않습니다.
- "Success. No rows returned"가 나오면 끝입니다. 빨간 오류가 나오면 글자를 그대로 복사해서 알려 주세요.
- 사이트 화면은 GitHub에 올리면 1~2분 뒤 자동으로 바뀝니다. 업데이트는 **경매 시작 전**에 하세요(경매 중이면 화면을 새로고침해야 새 버전이 적용됨).

## 5. 새 발로란트 요원이 나왔을 때

1. GitHub 저장소 → **Actions** → **Update agent icons** → **Run workflow**
2. 1~2분 뒤 새 요원이 신청 화면의 주 요원 목록에 아이콘과 함께 자동으로 추가됩니다.

## 6. 개인정보 요청 처리

모으는 정보: 디스코드 표시 이름·아이디·프로필 사진 주소·디스코드 번호, 신청서 내용(닉네임·티어·포지션·주 요원·각오). 로그인 서비스(Supabase)는 디스코드 이메일도 보관하지만 사이트는 쓰지 않습니다. 참가자는 신청할 때 개인정보 안내에 동의해야 합니다.

"내 정보를 지워 주세요" 요청이 오면
1. **신청 정보**: 운영자 콘솔 → 그 회차 → 참가자 탭 → **지우기**. (이미 경매 선수로 올라갔으면 경매 준비에서 빼고 다시 채운 뒤 지우기)
2. **지난 회차까지 모두**: 그 회차 전체를 지워도 되면 **회차 지우기**(진행 기록 속 참가자 이름도 가려짐).
3. **로그인 기록까지**: Supabase 대시보드 → **Authentication** → **Users** → 그 사람(디스코드 이름으로 찾기) → **Delete user**.

지켜 주세요
- 운영자는 꼭 필요한 사람만. 그만둔 운영자는 바로 **빼기**.
- 명단 CSV·엑셀 파일은 운영진끼리만 보관하고, 다 쓰면 지우세요.

## 7. 백업

무료 요금제는 자동 백업이 없습니다. 회차가 끝나면 아래를 받아 두세요.
- 경매 결과 탭 → **엑셀로 내려받기**
- 참가자 탭 → **명단 CSV로 내려받기**
- 필요하면 기록 탭 → **CSV로 내려받기**

## 8. 절대 하지 말 것

- Supabase의 **service_role** 키나 **secret** 키(`sb_secret_`으로 시작)를 어디에도 붙여 넣지 마세요. 사이트의 config.js에는 **publishable** 키만 들어갑니다.
- 디스코드 개발자 포털의 **Client Secret**을 채팅이나 사이트에 올리지 마세요.
- 진행자 화면 링크, 운영자 초대 링크를 공개 채널에 올리지 마세요.
- 돈이 드는 요금제로 바꾸지 않아도 됩니다. 지금 구성은 전부 무료입니다.
