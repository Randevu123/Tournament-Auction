# Tournament-Auction

발로란트 내전용 선수 포인트 경매 웹사이트입니다. 진행자가 경매를 열고, 팀장들이 각자 폰이나 PC로 실시간 입찰해 팀을 꾸립니다.

## 파일

| 파일 | 하는 일 |
| --- | --- |
| `index.html` | 진행자 화면: 경매 만들기, 시작, 일시정지, 마감, 다음 선수, 순서 추첨, 선수 관리, 팀장 링크, 채팅 |
| `screen.html` | 방송 화면(OBS 브라우저 소스용): 버튼 없이 보기만. 지금 선수·최고가·남은 시간·다음 순서·팀 카드, 낙찰 연출, 끝나면 결과 발표. 채팅과 디스코드 이름은 안 보임 |
| `team.html` | 팀장 화면: 자기 팀 입찰 버튼만 있음. 진행자에게 받은 전용 링크로 들어옴 |
| `signup.html` | 참가 신청 화면: 디스코드로 로그인한 뒤 게임 닉네임, 최고/현재 티어, 포지션을 골라 신청. 같은 디스코드 계정은 한 번만 |
| `admin.html` | 운영자 콘솔: 디스코드 로그인. 회차 만들기, 일정·신청 마감, 참가자 고치기·지우기·메모·팀장 배정, 티어 검수·점수 재확인(운영자 2명), 할 일, 운영자 초대·승인 |
| `practice.html` | 혼자 연습판: 온라인 경매와 같은 규칙으로 한 화면에서 연습 (서버 없음) |
| `common.js` | 규칙 숫자(시작 포인트, 입찰 단위 등), 티어 점수표, 서버 연결, 채팅 |
| `common.css` | 화면 모양 |
| `config.js` | Supabase 연결 정보 (주소와 anon/publishable 키) |
| `setup.sql` | Supabase SQL Editor에 한 번 붙여 넣는 설정 |

## 규칙 (기본값, `common.js`의 `CONFIG`에서 바꿈)

- 5팀, 팀마다 팀장 1명 포함 5명, 시작 포인트 1000P
- 입찰 단위 5P. 이번 선수를 산 뒤 남는 빈자리 1칸마다 5P를 남겨 둬야 함
- 선수당 15초. 입찰할 때마다 +5초, 최대 30초
- 유찰되면 순서 맨 뒤로. 두 번째 유찰이면 빈자리가 있는 팀에 무작위로 배정(0P)
- 티어 점수: 아이언1 = 1점부터 한 칸마다 +1점, 레디언트 = 25점. 선수 점수 = (최고 티어 + 현재 티어) ÷ 2

## 동시 입찰 처리

모든 판정은 서버(`setup.sql`의 함수)가 합니다. 입찰이 들어오면 서버가 경매 줄을 잠그고 한 건씩 처리하기 때문에, 여러 팀이 동시에 눌러도 먼저 도착한 입찰 하나만 인정됩니다. 표는 바깥에서 직접 읽거나 쓸 수 없고, 링크에 든 열쇠로만 조작할 수 있습니다.

## 참가 신청 (디스코드 로그인)

- 진행자 화면의 "팀장 링크" 또는 "신청 명단"에서 **참가 신청 링크**를 복사해 디스코드 서버에 올립니다.
- 신청 링크에는 경매 번호 대신 신청 전용 코드가 들어 있어, 링크가 공개돼도 경매와 채팅은 볼 수 없습니다.
- 디스코드 이름은 브라우저가 보낸 값이 아니라 서버가 로그인 정보에서 직접 가져옵니다.
- 로그인은 Supabase Auth의 Discord 로그인을 씁니다. (Discord 앱 등록 + Supabase에서 Discord 켜기 필요)

## 운영자 콘솔 (`admin.html`)

- **제작자 등록**: 진행자 화면(`index.html`)의 "운영자 콘솔" 버튼으로 들어가 디스코드로 로그인하면, 그 계정이 제작자(사이트 주인)로 등록됩니다. 한 번 등록되면 다른 사람은 제작자가 될 수 없고, 그 뒤로 새 회차는 운영자 콘솔에서만 만들 수 있습니다.
- **운영자 초대**: 제작자가 초대 링크를 보내면, 받은 사람이 디스코드로 로그인해 요청하고, 제작자가 승인합니다. 초대 링크는 언제든 새로 바꿀 수 있습니다.
- **회차**: 회차마다 신청 시작·마감, 경매 일시, 경기 일시를 정합니다. 경매가 끝났거나 경기 일시가 지난 회차는 목록 아래 "지난 회차"에 따로 모입니다(접기/펼치기). 신청은 "일정대로 자동 / 지금 열기 / 지금 마감" 중 하나로 운영합니다.
- **교차검수**: 참가자마다 "티어 검수"와 "점수 계산 재확인"을 서로 다른 운영자 2명이 확인해야 완료됩니다. 티어를 고치면 그 사람의 검수는 처음부터 다시 합니다.
- **진행 기록**: 누가 언제 무엇을 고쳤는지(이전 값 → 바뀐 값) 모두 남습니다. 회차별 "기록" 탭과 운영자 관리 화면의 전체 기록에서 보고 찾을 수 있고, 기록은 고치거나 지울 수 없습니다. "CSV로 내려받기"로 엑셀·구글 시트용 파일(최근 1000개)을 받을 수 있습니다.
- **권한**: 진행자 화면·팀장 링크는 그 회차의 진행자와 제작자만 봅니다. 운영자 메모는 참가자에게 보이지 않습니다.

## 배포

`main`에 새 버전이 올라가면 `.github/workflows/pages.yml`이 GitHub Pages에 자동으로 올립니다. (Settings → Pages → Source가 "GitHub Actions"여야 합니다.) 자동 배포가 안 되면 Actions 화면의 "Deploy site to GitHub Pages" → "Run workflow"로 직접 배포할 수 있습니다.

## 역할

- **제작자**: 사이트 주인. 운영자 콘솔 전체를 보고, 운영자를 초대·승인·빼기, 모든 회차의 진행자를 정하거나 회차를 지울 수 있습니다. (진행자 화면의 "운영자 콘솔" 버튼으로 처음 들어와 등록)
- **운영자**: 제작자에게 초대받아 승인된 사람. 참가자 명단(고치기·지우기·메모·팀장★·교차검수), 일정, 할 일을 관리합니다.
- **진행자**: 회차마다 한 명. 그 회차를 만든 운영자가 진행자가 되고, 진행자나 제작자가 다른 운영자에게 넘길 수 있습니다. 경매 준비·진행자 화면/팀장 링크·회차 지우기는 그 회차의 진행자와 제작자만 합니다.

## 경매 준비 (운영자 콘솔 → 회차 → "경매 준비" 탭)

1. **명단·팀장·핸디캡**: 경매에 넣을 사람(포함)과 팀장(★, 누른 순서가 팀 순서), 팀장별 핸디캡을 정하고 "이 명단으로 경매 선수 채우기". 팀 수 = 팀장 수(최대 8).
2. **경매 설정**: 시작 포인트·입찰 단위·팀 인원·빈자리 몫·핸디캡(경매 시작 전만), 티어 점수표와 최고/현재 티어 비율(언제든).
3. **팀장 링크**: "팀장 링크 한 번에 복사".
4. **순서**: 무작위로 섞기 또는 ▲▼로 직접 정한 뒤 확정. 방송용 추첨 연출은 진행자 화면의 "방송용 순서 추첨".
- 선수 티어·점수는 "참가자" 탭의 "고치기"에서 바꿉니다(부계정은 점수 직접 입력). 경매 중에 고쳐도 모든 화면의 팀 합계·평균에 바로 반영됩니다.
- 선수 점수 = 직접 정한 점수가 있으면 그 점수, 없으면 `최고 티어 점수 × 비율 + 현재 티어 점수 × (1 − 비율)`.
- **회차 지우기**: "일정" 탭 아래. 회차 이름을 똑같이 적어야 지워지고, 진행 기록은 남습니다.

## 연습판 (`practice.html`)

서버 없이 한 화면에서 온라인 경매와 같은 규칙(팀장 1~8명, 빈자리 몫, 핸디캡, 점수표·비율, 점수 직접 입력, 무작위/직접 순서, 입찰 단위 버튼)으로 연습합니다. 한 사람이 모든 팀 버튼을 누르고, 선수·설정은 그 브라우저에만 저장됩니다.

## 경매 결과 (엑셀)

- 경매가 끝나면 진행자 화면·팀장 화면·연습판에 **경매 결과**(팀별 최종 명단, 남은 포인트, 점수 합계·평균)가 뜨고, **엑셀로 내려받기** 버튼으로 `.xlsx` 파일을 받습니다. 운영자 콘솔의 "경매 결과" 탭에서도 받을 수 있습니다(경매 중이면 지금까지의 팀 구성).
- 시트 "팀 구성": 팀, 구분(팀장/낙찰/유찰 → 무작위 배정), 선수 닉네임, 디스코드 이름, 최고 티어, 현재 티어, 티어 점수, 포지션, 낙찰가, 비고.
- 시트 "팀 요약": 팀, 팀장, 인원, 시작 포인트, 핸디캡, 쓴 포인트, 남은 포인트, 티어 점수 합계·평균. 팀에 못 들어간 선수가 있으면 시트가 하나 더 생깁니다.
- **방송용 결과 발표**: 진행자 화면·연습판에서 경매가 끝나면 팀 카드가 티어 점수 합계가 낮은 팀부터 한 장씩 등장하고, 마지막에 합계 1위 팀이 "우승 후보"로 강조됩니다("결과 발표 다시 보기"로 다시 재생). 모든 결과 화면에 "점수 합계 N위"가 붙습니다. 순위는 신청 티어 점수표 합계만 씁니다.
- 엑셀 파일은 SheetJS(무료, Apache-2.0)로 만들고, 불러오지 못하면 CSV로 대신 받습니다.

## 방송 화면 (`screen.html`, OBS)

- **링크**: 운영자 콘솔 → 회차 → "링크" 탭(또는 "경매 준비" 탭의 "방송 화면 열기"), 진행자 화면의 "팀장 링크" 창에 "방송 화면 (OBS)"로 있습니다. 회차마다 따로 있는 보기 전용 링크라, 새어 나가도 경매를 조작하거나 입찰·채팅을 할 수 없습니다.
- **OBS 넣는 법**: 소스 추가 → 브라우저 → URL에 방송 화면 링크, 너비 1920, 높이 1080. 다른 크기여도 화면 비율에 맞춰 줄어듭니다.
- **보이는 것**: 준비 중에는 "선수 경매 곧 시작"과 팀장, 경매 중에는 지금 선수 카드·최고가와 입찰 팀·남은 시간(+초 표시)·다음 순서·팀 카드(최고가 팀 강조), 낙찰·유찰 번쩍 연출, 끝나면 결과 발표(한 팀씩 등장, 1위 "우승 후보"). 키보드 R(OBS "상호작용")로 결과 발표를 다시 재생합니다.
- 채팅과 디스코드 이름은 방송 화면에 나오지 않습니다. 서버의 채팅 함수도 방송 화면 링크로는 읽을 수 없게 막혀 있습니다.

## 지난 회차 잠금

- 경매가 끝났거나 경기 일시가 지난 회차는 잠깁니다: 참가자 고치기·지우기·팀장·검수, 일정·신청 설정, 경매 준비, 진행자 화면의 "처음부터 다시"(결과 보호), 새 신청이 막힙니다. 할 일·기록·CSV·결과 내려받기는 됩니다.
- 제작자만 "잠금 풀기 / 다시 잠그기"를 할 수 있고, 기록에 남습니다.

## 서비스 상태 (무료 요금제 7일 정지 대비)

- 운영자 콘솔 오른쪽 위에 "서버 정상 · 응답 ms"가 보이고, 누르면 서비스 상태 카드(마지막 사용 시각, 데이터베이스 사용량/무료 500MB, 회차·신청 수)가 나옵니다.
- 운영자 콘솔을 열 때마다(켜 둔 동안 10분마다) '사용 중' 기록을 남겨 7일 정지 시계를 다시 셉니다. **내전 전날 운영자 콘솔을 한 번 열어 두면 됩니다.**
- **자동 깨우기**: `.github/workflows/keepalive.yml`이 3일마다 서버를 한 번 불러 멈추지 않게 합니다(GitHub Actions, 무료). 마지막 자동 깨우기 시각은 서비스 상태 카드에 보입니다. Actions 화면의 "Keep Supabase awake" → "Run workflow"로 바로 실행해 볼 수 있습니다.
- 서버에 연결되지 않으면 Supabase 대시보드에서 "Restore project"로 다시 켜는 방법을 안내합니다.
